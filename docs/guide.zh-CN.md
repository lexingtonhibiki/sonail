# 第一个项目

侧边栏“使用指引”始终可打开，会显示当前项目目录、已合入任务数，并带你进入下一步。可以点“载入两任务示例”先体验导入：示例只填入编辑区，检查后确认才创建卡片，建议使用独立演示项目。

1. 安装 Node.js 22/24、Git 和准备使用的 harness，先在 harness 原生入口登录。
2. 运行 `Setup.cmd`，再运行 `Open-Sonail.cmd`。默认后台19100、页面19101，解压目录保持固定。
3. 新建项目，选择已有初始提交的 Git 仓库。执行者使用独立 worktree；主目标未提交修改会阻止合入。
4. “角色与设置”分别配置经理、执行者、审查者。OpenCode 从本机提供方目录发现模型；不要假设模型免费或支持所有思考等级。
5. 填写原始想法，让经理起草，再核对确认。无需调用模型的入门示例：将 `examples/demo.zh-CN.json` 粘贴到“想法与规格 → 手动导入JSON”。依赖使用前序任务从0开始的索引。
6. 启动解锁的卡片，在“经理记录”看精简意见；任务详情中的“原始执行过程（高级）→ 详细执行过程”可看实时记录，主要操作跟随中英切换，模型原文保持原样。复制交接包会显示反馈。
7. 审查者按条件取证，阻塞问题需返工，可选建议不阻断。经理把控与项目目标的一致性，人工条件仍等你体验。
8. 满意后验收，在卡片上“合入项目”，系统重核版本和指纹，再解锁下游。重开会使下游假设失效，移动卡片不能替代验收。

## 自动推进

默认手动。“完全托管”披露并同步自动推进、客观验收、合入和经理补充执行指导四项权限；保留人工体验、并发和返工上限。经理补充指导不能重写项目目标或验收条件。暂停不会撤销已经执行的命令。

## 启动与恢复

“集成与外观 → 服务与启动”管理当前用户 Windows 登录自启动和桌面入口。登录启动不弹浏览器；AI 重启暂停，请核对记录后恢复。

端口占用时不杀无关进程；查看 `data/runtime/launcher.log`。停止本实例用 `停止Sonail.cmd`。手动指定端口：`powershell -File scripts/start-sonail.ps1 -ApiPort 19200 -UiPort 19201 -Open`，快捷方式仍使用默认端口。

停服后备份整个 `data/`，不要提交到仓库。接口密钥目前本地明文存储，系统密钥库接入待做。

## 预览边界

已验证产品路线是 Windows 启动入口和默认 SQLite 工作流。上游 PostgreSQL/容器能力保留源码，未作为 Sonail 部署路线验收。模型适配受账号实际能力限制。尚无长期原生经理会话、任意插件加载、余额查询和刷新预测UI。
